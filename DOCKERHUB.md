# Nexploy agent

Connect a remote Docker host to [Nexploy](https://hub.docker.com/r/nexploy/nexploy) without exposing the Docker
daemon on the network. The agent runs on the target host, dials your Nexploy server over an outbound WebSocket and
bridges the Docker API through that single connection.

- **Source:** https://github.com/Nexploy/agent
- **Companion images:** [`nexploy/nexploy`](https://hub.docker.com/r/nexploy/nexploy), [`nexploy/docker-api`](https://hub.docker.com/r/nexploy/docker-api) and [`nexploy/build-runner`](https://hub.docker.com/r/nexploy/build-runner)

No inbound port to open, no TLS certificate to generate, works behind NAT.

## Pull

```bash
docker pull nexploy/agent:latest
```

## Run

In Nexploy, create an environment with the **Agent** connection type, copy the generated token, then run on the
target host:

```bash
docker run -d \
  --name nexploy-agent \
  --restart unless-stopped \
  -e NEXPLOY_URL=https://nexploy.example.com \
  -e NEXPLOY_AGENT_TOKEN=nxa_xxxxxxxxxxxxxxxxxxxxx \
  -v /var/run/docker.sock:/var/run/docker.sock \
  nexploy/agent:latest
```

The environment turns online in Nexploy as soon as the tunnel is established.

## Configuration

| Variable | Default | Description |
| --- | --- | --- |
| `NEXPLOY_URL` | *required* | Base URL of the Nexploy server |
| `NEXPLOY_AGENT_TOKEN` | *required* | Agent token generated by Nexploy (`nxa_…`) |
| `DOCKER_SOCKET_PATH` | `/var/run/docker.sock` | Docker socket to bridge |
| `NEXPLOY_AGENT_HEALTH_PORT` | `9091` | Health endpoint port, `0` disables it |
| `NEXPLOY_INSECURE_SKIP_TLS_VERIFY` | `false` | Skip TLS verification of the Nexploy server |
| `LOG_LEVEL` | `info` | pino log level |

## Health

- `GET /healthz` — the process is alive
- `GET /readyz` — `200` while the tunnel is connected, `503` otherwise

## Security

The agent gives the Nexploy instance holding its token full control over the Docker daemon it is mounted on: creating
containers, reading logs, opening terminals, deleting volumes. Treat the token like a root credential — it is shown
once, stored hashed, and can be regenerated from the environment settings, which immediately invalidates the old one.

Traffic only ever flows outbound from the host to Nexploy, over the same TLS as the web UI.
